# Spec: Memory v2 — retention tiers, categories, tags, browsable + indexed

Date: 2026-08-01. User ask: permanent AND temporary (7/30/60-day) memory
retention; categorise and tag memories; make memory genuinely browsable;
improve indexing for the AI. Also closes a standing gap: the Settings
retention window is persisted but pruning was NEVER enforced.

## Objective

Every memory carries provenance (already), a category, derived tags, and
a retention tier. The user can browse by category/tag, pin memories
permanent, or give one an explicit 7/30/60-day expiry. A prune loop
finally enforces the global window and per-memory expiries. Search
matches tags and categories so the AI's recall sharpens.

## Design

### Schema (additive migration, the `source` pattern)
- `category TEXT NOT NULL DEFAULT 'other'` — one of a FIXED taxonomy:
  development, browsing, communication, writing, media, shopping,
  reference, personal, system, other. Closed set: chips stay renderable,
  search stays predictable.
- `tags TEXT NOT NULL DEFAULT '[]'` — JSON array of ≤5 lowercase
  keywords. Derived MECHANICALLY at insert (the graph's stopworded
  keyword extraction, moved to a shared home) — deterministic, works for
  every source, no fragile model-output parsing. `remember` may pass
  explicit tags. Existing rows are backfilled at migration.
- `pinned INTEGER NOT NULL DEFAULT 0` — permanent; pruning never touches.
- `expires_at_ms INTEGER` — NULL means "standard" (follow the global
  window); a value is an explicit per-memory expiry.

### Categorisation
- Watcher distillation: the thin-lane prompt now emits `category: summary`
  per line; parsing is LENIENT (unknown/missing category → other; the
  summary is never lost to a format miss).
- Chat-derived memories: fixed category `communication` (the distiller
  already runs on conversation text; a second model pass isn't worth it).
- `remember` (told): optional `category` arg, default `personal`; told
  memories default PINNED (a fact the user asked to keep should not
  silently expire).

### Retention enforcement (new)
- Pure store method `prune_expired(now_ms, global_window_ms)` deletes
  un-pinned rows whose explicit expiry passed, or (when a global window is
  set) whose `created_at_ms` fell outside it. Pinned rows are untouchable.
- A daily loop (first tick at boot) reads the persisted retention setting
  each tick. The Settings hint stops saying "ships later".

### Browsing (memory window)
- Timeline rows gain a category chip, tag chips (click = filter), a pin
  star toggle, and an expiry select (Standard · 7d · 30d · 60d ·
  Permanent).
- A category facet row above the timeline filters by category.
- `filterRecords` matches summary + apps + tags + category.

### Indexing for the AI
- Keyword search haystack becomes summary + tags + category.
- `memory_search`/graph payloads carry category + tags (pixel-free).

## Boundaries
- Always: additive migration only; lenient parses; pinned rows never
  pruned; full battery per commit.
- Never: model-dependent tags; destructive migration; auto-pruning told/
  pinned rows.

## Success criteria
1. A pre-v2 database opens, gains columns, and backfills tags.
2. Distilled memories carry a category; garbage category degrades to
   `other` with the summary intact.
3. Pruning: explicit expiry beats the global window; pinned survives
   everything; the loop runs at boot + daily.
4. Timeline filters by category chip and tag click; pin + expiry are
   settable per row and survive restart.
5. memory_search finds a memory by tag alone.
